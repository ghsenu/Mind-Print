Cloud Firestore Collections, Fields & Security Rules



# 1. Database Overview
MindPrint uses Cloud Firestore as its primary NoSQL database. Data is organized in collections and sub-collections following a user-centric document model. All documents are scoped to individual users to ensure privacy and data isolation.

| Property | Value |
|---|---|
| Database Type | Cloud Firestore (NoSQL Document Store) |
| Mode | Native mode |
| Region | asia-south1 (Mumbai — closest to Sri Lanka) |
| Offline Support | Enabled (Firestore offline persistence) |
| Security | Firestore Security Rules (user-scoped) |

# 2. Collection Structure
## 2.1 users/{userId}
Stores user profile information created on registration.

| Field | Type | Description |
|---|---|---|
| userId | String | Firebase Auth UID (document ID) |
| displayName | String | Full name from registration |
| email | String | User email address |
| profilePhoto | String (URL) | Firebase Storage URL for profile image |
| language | String | Selected language: "en" | "si" | "ta" |
| yearOfStudy | String | Captured during onboarding questionnaire |
| biometricEnabled | Boolean | Whether biometric login is active |
| notificationsEnabled | Boolean | Push notification preference |
| offlineSyncEnabled | Boolean | Offline sync preference |
| createdAt | Timestamp | Account creation date |
| lastActiveAt | Timestamp | Last app open timestamp |
| onboardingCompleted | Boolean | Whether onboarding questionnaire was completed |

## 2.2 users/{userId}/onboardingData/{docId}
Stores baseline responses from the onboarding questionnaire. Used to seed the mood prediction model.

| Field | Type | Description |
|---|---|---|
| mainStressSource | String | "study" | "work" | "personal" | "multiple" |
| anxietyFrequency | String | "rarely" | "sometimes" | "often" | "almost_always" |
| currentStressLevel | Number | Scale 1–5 (slider input) |
| joySource | String | Free text — what brings the user joy |
| completedAt | Timestamp | When questionnaire was submitted |

## 2.3 users/{userId}/journals/{journalId}
Core journal entries collection. Each document represents one journal entry (text or voice).

| Field | Type | Description |
|---|---|---|
| journalId | String | Auto-generated document ID |
| entryType | String | "text" | "voice" |
| textContent | String | Written journal text (or voice transcription) |
| audioUrl | String (URL) | Firebase Storage URL for voice recording (voice entries only) |
| moodSelected | String | User-selected mood: "sad"|"neutral"|"happy"|"overjoyed" |
| createdAt | Timestamp | Entry creation date and time |
| isAnalyzed | Boolean | Whether AI analysis has been completed |
| isOfflineEntry | Boolean | Whether entry was created offline |
| hashtags | Array<String> | AI-generated hashtags e.g. ["#nature", "#MorningRoutine"] |

## 2.4 users/{userId}/journals/{journalId}/emotionResult/{resultId}
Sub-collection storing AI emotion analysis results for each journal entry.

| Field | Type | Description |
|---|---|---|
| primaryEmotion | String | Top detected emotion e.g. "Calm" |
| primaryIntensity | Number | Confidence score 0–100 (percentage) |
| secondaryEmotions | Array<String> | Secondary detected emotions e.g. ["Grateful", "Reflective"] |
| emotionBreakdown | Map | Full breakdown: {peaceful: 60, thoughtful: 70, anxious: 20} |
| aiInsight | String | MindPrint AI-generated reflection text |
| distortionDetected | Boolean | Whether cognitive distortion was identified |
| distortionType | String | Type of distortion if detected e.g. "Catastrophising" |
| cbtSuggestion | String | CBT reframing suggestion if distortion detected |
| analysisSource | String | "huggingface_nlp" | "assemblyai_ser" |
| analyzedAt | Timestamp | When analysis was completed |

## 2.5 users/{userId}/moodCheckins/{checkinId}
Quick mood check-ins from the Home Dashboard. Feeds into mood prediction analytics.

| Field | Type | Description |
|---|---|---|
| mood | String | "sad" | "neutral" | "happy" | "overjoyed" |
| moodScore | Number | Numerical mapping: sad=1, neutral=2, happy=3, overjoyed=4 |
| createdAt | Timestamp | Date and time of check-in |

## 2.6 users/{userId}/predictions/{predictionId}
Stores mood prediction results generated by the daily scheduled Cloud Function.

| Field | Type | Description |
|---|---|---|
| forecastPeriod | String | "next_48_hours" |
| predictedTrend | String | "stable" | "improving" | "declining" |
| dipPredicted | Boolean | Whether a mood dip is predicted |
| confidenceScore | Number | Prediction confidence 0–100 |
| basedOnDays | Number | Number of days of data used (max 7) |
| generatedAt | Timestamp | When prediction was generated |
| alertSent | Boolean | Whether FCM notification was sent for this prediction |

## 2.7 users/{userId}/notifications/{notificationId}
Stores in-app notifications displayed in the notification screen.

| Field | Type | Description |
|---|---|---|
| type | String | "affirmation" | "journal_reminder" | "mood_alert" | "sync_complete" |
| title | String | Notification title text |
| body | String | Notification body text |
| isRead | Boolean | Whether user has viewed this notification |
| deepLinkTarget | String | Screen to navigate to on tap e.g. "/analytics" |
| createdAt | Timestamp | When notification was created |

## 2.8 users/{userId}/reports/{reportId}
Metadata for generated export reports.

| Field | Type | Description |
|---|---|---|
| reportId | String | Auto-generated document ID |
| format | String | "pdf" | "csv" |
| dateRangeStart | Timestamp | Report start date |
| dateRangeEnd | Timestamp | Report end date |
| fileUrl | String (URL) | Firebase Storage URL for generated file |
| generatedAt | Timestamp | Report generation timestamp |
| entryCount | Number | Number of journal entries included |

# 3. Firestore Security Rules
All Firestore documents are protected by security rules that ensure users can only access their own data. No cross-user data access is permitted.

Core Security Rule Logic:
Authenticated users may read and write only to paths under users/{their own userId}/
Unauthenticated requests are denied for all user data collections
Admin-level operations are handled exclusively by Cloud Functions using Firebase Admin SDK
All rule violations are logged to Firebase Security Rules audit log
